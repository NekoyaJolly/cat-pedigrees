# 血統書Web版：PC・モバイルの画面設計案

状態：2026年10月18日に利用者から「OK、実装しよう」と承認を受け、実装。以下の比較表は承認時の判断とトレードオフを記録したもの。

## 現在の状態と今回の方針

`cat-pedigrees` には、ログイン、検索・一覧、新規登録、編集、きょうだい登録、印刷・PDFの画面が既にある。今回の調査では、このリポジトリに接続したVercelプロジェクトとPRプレビューは確認できなかった。画面の有無と、Vercelへの公開状況は別である。

今回は単体の `cat-pedigrees` を土台にする。検索・登録・印刷の既存処理を使い、モバイルでの入力と視認性を整える。MyCats ProやHUBとの統合は今回の対象に含めない。

PCはAccessで使い慣れた呼び出し・入力・きょうだい登録の流れと、3世代を並べて確認できる配置を生かす。Accessの登録フォーム自体の画像は今回確認できていないため、見た目まで同じとは扱わない。

## 確認した範囲

- コード：`PedigreeForm.tsx`、`FormInput.tsx`、`data-table.tsx`。
- 表示：既存のローカル検証で取得したPC・390px幅のフォーム画像。合成データを使用。
- 設計時点では実機操作、ソフトキーボード表示、タブレット表示、利用者による操作時間の測定は行っていない。実装後のブラウザー検証は末尾に記載する。

## 登録・編集フォームの案

入力は一つのフォームのままにする。保存までに全ページを順番に進む手順は加えない。

1. 編集対象の名前・本猫IDと、未保存状態を確認できるようにする。新規登録時のIDは保存時に決まることを示す。
2. 本猫の名前、猫種、性別、色柄、誕生日などを入力する。コード欄は対応する名称を読み取れる大きさで併記する。
3. 父・母のIDで呼び出すと、その猫と先祖の情報が入る。既存の世代シフトを維持する。両親IDによる同じ血統のコピーも維持する。
4. スマホでは祖父母・曾祖父母を名前とナンバーで確認し、修正する猫だけ入力欄を開く。未入力も判別できるようにし、すべての項目へ到達可能にする。
5. 保存と、「内容を確認」「印刷」「印刷してきょうだいを続ける」の選択肢を維持する。保存結果とエラーは対象フォーム内で示す。

先祖のナンバー重複は青文字で表示する。折り畳んだ状態でも重複を確認できるようにする。登録・印刷の番号と、呼び出しに使う数字IDの区別を維持する。

## 実装時の確認条件

- スマホ390px幅・文字拡大時に、名前・項目名・入力値・エラーが読める。
- キーボード表示中と閉じた後に、入力欄と保存操作が重ならず、最後の項目にも到達できる。これは実機での確認事項とする。
- 父・母の呼び出しと世代シフト、先祖ナンバーの重複表示、きょうだい登録、未保存警告を維持する。
- PCでは3世代の比較とキーボード操作を確認する。タブレット幅では切替前後の折り返しを確認する。
- 既存の登録・再表示・競合検知・印刷の動作を検証する。本番データをUI検証用に変更しない。
- 印刷用339mm × 239mmのPDF寸法は、画面の見やすさの調整とは分けて維持する。

実装前の設計確認は、このリポジトリの `AGENTS.md` にある「コード生成前に必ず設計案を提示し、ユーザーの『OK』を得てから実装に進むこと」に従う。UIレビューの `review-practical-uiux` でも「L3は明示的な承認が得られるまで実装対象にしない」と定めている。

## 実装した表示と操作

- フォームは1024px未満で先祖欄を開閉し、1024px以上で3世代を並列表示する。入力欄自体は一組で、開閉・画面幅の変更で編集値を失わない。
- 本猫情報は768px以上で2列、1024px以上で3列。スマホの項目名は14px、入力値は16pxを基本とし、入力・主要操作は44px以上の高さを確保した。文字サイズの拡大に合わせて操作ボタンも大きくなる。
- 検索結果は1280px未満で主要情報の行、1280px以上で8列の表。どちらも同じ検索結果・絞り込み・ページ切替を使う。
- 保存結果・エラーは保存欄の近くに表示する。利用者が先祖を編集した位置からも結果を確認できる。
- 閲覧専用の場合も開閉は使える。入力欄と保存は無効にする。
- 表示領域の縮小に合わせて保存欄の位置と入力欄のスクロール位置を調整する。端末固有のキーボード動作は実機確認を残す。
