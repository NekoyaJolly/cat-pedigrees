# 新規画面から戻った時の入力状態

## 期待する表示

空の新規登録・きょうだい登録では、既存の猫を対象とする「きょうだいを登録」「印刷」を表示しない。元の猫の編集へ戻った時は、その猫の情報と2つのボタンを表示する。この表示条件は変更しない。

2026年10月18日、利用者から2つのボタンが戻らないとの報告を受けた。その後、本人から勘違いだったかもしれないとの補足を受領した。本人の操作と同一であることは未確認だが、以下のキャッシュ復帰の不具合を別途再現できたため修正する。

## 確認した不具合と修正

新規画面で本猫IDを呼び出し、空のきょうだい画面へアプリ内遷移して履歴を戻すと、URLは元の猫を示すのに見出しが新規登録、名前が空欄、2つのボタンが非表示になった。通常の読み直しを伴う6経路では修正前も再現しなかった。

原因は全フォームで同じZustand状態を使い、画面復帰時にサーバーから渡された最初の値で初期化していたこと。さらに同じ新規ページ内で通常の新規ときょうだいを切り替えると、キーの変更で元の入力状態が失われていた。

- 状態をページ単位で作成し、そのページ内でも通常の新規とコピー元別のきょうだい登録を別の状態として保持する。別の画面の変更・遅れて届いた呼び出し結果を混ぜない。
- ページ内の状態の入れ物を維持し、最初に生成した時だけ初期値を適用する。キャッシュから戻った際には呼び出した猫と下書きを再利用する。
- 未保存状態も同じ範囲で保持する。保存・両親コピーで使う最新値は、その画面専用の状態から取得する。
- 空の画面から戻るだけではDBへ保存せず、新しい行も作らない。ボタンの表示条件、保存対象、世代シフト、競合検知、印刷とレイアウトは変更しない。

## 検証

単体テストは状態の分離・復帰と非同期更新の分離を2件追加し、計11件が成功。型チェックを含む本番用ビルドも成功した。

合成DBとローカル認証で、直接開いた猫・ID呼び出しで開いた猫それぞれから「新しい猫」「ヘッダーの新規登録」「きょうだいを登録」へ進んで戻る6経路を確認した。アプリ内キャッシュからの戻る・進むを繰り返し、元の猫のID・名前・2ボタンとリンク先、両画面の未保存内容が保たれることを確認した。復帰後の保存は元の猫だけを更新し、全13,812件の合成データの件数は増えていない。

配置と既存の業務フロー17項目、ID自動呼び出し・非表示データ保持11項目も再検証し、成功した。既存の血統データの変更は行っていない。ブラウザー自体の履歴キャッシュは実行環境で無効であり、端末固有の復元動作は未確認。アプリ内キャッシュの検証ではNext.jsの公開ルーターを使って遷移し、修正前の再現と修正後の復帰を確認した。実機での受入と実際の台紙への印刷は未確認。
