# 業務用フォームの入力幅と配置

## 今回の範囲

2026年10月18日、利用者から印刷以外の動作確認が済んだとの報告と、説明を省いた業務用の画面、入力する桁数に合わせた欄幅への改修依頼を受けた。この依頼を実装範囲とする。既存の一つのフォーム、保存、呼び出し、先祖の開閉、PCの3世代表示を維持し、欄幅・並び・余白・文言を調整する。

既存Supabaseの`pedigrees`全13,868件を読み取り専用で集計した。空欄を除いて前後の空白を取り除いた文字数を使い、個別の猫名・所有者名はこの文書へ転記していない。現時点の分布を表示幅の判断に使い、保存できる文字数の制約には変換しない。

## 入力幅の根拠

95%値は、入力済みの値の95%が収まる文字数を示す。幅は数字の幅を基準にし、左右の余白と項目名が収まる最低幅を加える。画面より広い欄は画面内へ収める。

| 項目 | 95%値 | 最大値 | 表示幅の方針 |
| --- | --- | --- | --- |
| 本猫・呼び出しID | 6桁 | 6桁 | 今後を見込んで7桁分 |
| 猫種コード | 2桁 | 3桁 | 3桁分。名称を右に併記 |
| 色柄コード | 3桁 | 3桁 | 3桁分。長い名称は右側で折り返す |
| 性別コード | 1桁 | 1桁 | 1桁分と項目名の最低幅。名称を右に併記 |
| 兄弟・姉妹の頭数 | 1桁 | 1〜2桁 | 2桁分と項目名の最低幅 |
| 誕生日・登録日 | 10文字 | 10文字 | 10文字分 |
| 本猫の名前・名前の続き | 18・16文字 | 23・17文字 | 26・24文字分 |
| 本猫の目色 | 6文字 | 10文字 | 10文字分。誕生日と同じ行へ配置 |
| 繁殖者・所有者 | 16文字 | 18文字 | 20文字分 |
| 本猫の称号 | 8文字 | 23文字 | 通常12文字分。長い既存値は欄内で編集可能 |
| 他団体No | 17文字 | 21文字 | 24文字分 |
| 摘要1・2 | 19・22文字 | 各32文字 | 日本語もあるため28文字分を基本とする |
| 父母・先祖の名前 | おおむね21〜23文字 | 305文字の例外あり | 26文字分。例外の値を切り詰めない |
| 先祖の称号 | 世代・父母別に8〜20文字 | 23文字 | 24文字分 |
| 父母・先祖のナンバー | 20文字 | 23文字 | 24文字分 |

マスタ全体では猫種112件、色柄407件、性別4件。名称の最大はそれぞれ20・33・6文字である。コード欄を名称の長さに合わせて引き伸ばさない。

## 検証

型チェック・本番用ビルドと、既存の単体テスト9件が成功。合成DBとローカル認証を使ったブラウザー検証15項目も成功した。新規・編集、父母の3世代展開、重複表示、競合検知、きょうだい登録、閉じた先祖の保存、閲覧専用、ログアウトを含む。今回はPDF本体を変更しておらず、実際の台紙への印刷は未確認。

幅改修の段階では320・390・768・1023・1024・1280・1440pxでフォームと一覧を確認し、390pxで文字200%に拡大しても横はみ出しがないことを確認した。スマホの入力文字16pxと入力・保存操作の高さ44px以上を維持した。続く欄高の変更は末尾に記載する。

最終の幅確認では、全7幅で呼び出し欄の実測が約82pxとなり、7桁の表示とカーソルの余白を確保した。10桁の値も保持できる。最大33文字相当の合成色柄名、3桁コード、2桁頭数でも横はみ出しはない。390pxでは誕生日・登録日・目色が同じ行に収まり、文字200%では折り返す。日本語フォントを設定した検証環境で、スマホ・タブレット・PCの画像も確認した。

実機の入力感と実際の台紙への印刷は利用者による確認対象とする。今回の表示確認で既存の血統データを変更していない。

## 項目名の欄内表示と高さ（同日追記）

利用者から「幅かなり良くなった」との報告を受領し、次に各欄の上部のラベルをなくして高さを減らすよう依頼された。項目名は欄の内側へ表示し、フォーカスすると消える形を指定されている。この具体的な依頼の範囲で、L1の表示・高さの調整を行う。

- 空欄・フォーカスなし：欄内に「名前」「猫種」「父猫ID」などの項目名を薄く表示する。
- フォーカス中：空欄でも項目名を消し、入力すると入力値だけを表示する。
- 空欄のままフォーカスを外す：項目名を再表示する。
- 入力済み：入力値だけを表示する。項目名を上に浮かせたり、別の段へ移したりしない。
- 本猫・父母・先祖と、上部のID呼び出し欄へ同じ方式を適用する。

さらに利用者から、入力欄自体も文字の高さに合わせ、上下の余白を極力なくすよう指定された。この新しい指定を優先し、従来の入力域44px以上という基準は今回の業務用フォームへ適用しない。入力欄の行高は文字サイズの1.25倍、上下の余白は0、枠線は上下各1pxとする。通常のスマホ表示は文字16px・枠込み約22px、PCは文字14px・枠込み約19.5px。文字拡大では文字サイズに比例して高さも拡大する。ID呼び出し欄と隣の呼出ボタンも同じ高さに揃える。

既存の欄幅を基本とし、候補の矢印があるコード・性別欄だけは、欄内の項目名と3桁の値が欠けない最低幅を確保する。通常のスマホで約68px、PCで約64px。それ以外の欄幅は変更しない。縦の密度が増える一方で、従来より指で狙える高さは小さくなり、入力後やフォーカス中は項目名を常時視認できなくなる。業務用として利用者が具体的に指定した表示方式を採用する。読み上げと項目の識別に使うラベルは画面外の扱いで保持し、欄内の項目名を保存データへ入れない。

変更後の型チェック・本番用ビルド、既存の単体テスト9件、合成DBでのブラウザー検証16項目が成功した。名前・コード・性別・頭数・父母・ID呼び出しの計10項目で、欄内の項目名、空欄のフォーカスだけでの消去、入力後の値だけの表示、空欄に戻した際の再表示を確認した。実測はスマホが入力域20px・枠込み22px、PCが入力域17.5px・枠込み19.5px。ID欄と呼出ボタンもスマホで22pxとなることを画面で確認した。

320〜1440pxの7幅、390pxで文字200%でも横はみ出しはなく、閉じた先祖の保存・再読込と父母の呼び出しも維持した。日本語フォントを使った空欄・フォーカス中・3桁コード入力後・PCの画像を確認し、「猫種」「色柄」「性別」と3桁のコードが欠けないことを確認した。実機の入力感は未確認。本番の血統データへの変更は行っていない。

## ID呼び出しの自動化と2項目の非表示（同日追記）

利用者から、本猫・両親・父猫・母猫のID欄の呼出ボタンをなくし、Enterまたは値のある欄からフォーカスを外した時に呼び出すよう、具体的な指示を受けた。本猫の「名前の続き」「摘要2」も画面から隠す。DB項目、読み込み、保存、印刷用の既存値は保持する。

Enter直後のフォーカス移動や、変更していないID欄への再訪では同じ内容を重ねて呼び出さない。明示的なEnterでの再呼び出しは可能とする。異なるID欄への連続入力は順番に反映し、待機中に入力されたIDが変わった場合は古い結果を適用しない。本猫を開く時の未保存確認は維持する。

呼び出し待ちで保存を選んだ場合は、呼び出しが終わってから最新のフォームを保存する。見つからないIDや通信エラーがある場合は、その欄のIDを修正・再試行するか、空欄へ戻すまで保存しない。非表示の2項目は空欄にせず、読み込んだ状態を保存処理へ引き継ぐ。

| 項目 | 内容 |
| --- | --- |
| 問題 | 呼出ボタンの操作が毎回必要で、低頻度の入力欄も常時表示される |
| 変更案 | 4つのID欄をEnter・フォーカス移動で呼び出し、「名前の続き」「摘要2」をフォームから非表示にする |
| 得るもの | ID入力から次の項目へ進むだけで呼び出せる。縦方向の入力欄が2つ減る |
| 失うもの | 呼び出す時期をボタンで選ぶ操作と、非表示の2項目をこの画面で編集する機能 |
| 代替案 | 呼出ボタンを残し、低頻度の2項目だけを隠す。利用者は今回、Enter・フォーカス移動への変更を指定した |
| 変更レベル | 呼び出しはL3の操作変更。2項目の非表示はL2 |
| 承認 | 本人が今回の具体的な動作と非表示項目を明示して承認済み。追加の確認は不要 |
| PCへの影響 | EnterとTab移動で呼び出せる。検索・入力の幅と3世代表示は維持 |
| スマートフォンへの影響 | 別の欄をタップすると呼び出せる。ボタンと2入力欄の面積を減らす |
| タブレットへの影響 | 同じ動作を適用し、収まる幅でID欄を折り返す |
| 操作数への影響 | 呼出ボタンを押す操作が不要。未保存の本猫を置き換える確認は維持 |
| 情報密度への影響 | 呼出ボタンと2入力欄を除き、入力文字や欄高は変更しない |
| 一覧性・俯瞰性への影響 | 検索一覧と先祖の表示を維持。非表示の2項目はこのフォームでは確認できない |

変更後の型チェック・本番用ビルド、単体テスト9件、既存のブラウザー検証16項目に成功した。さらに自動呼び出し用のブラウザー検証11項目にも成功し、実行時エラーはなかった。4欄それぞれのEnter・フォーカス移動、未変更の欄の再訪、Enter連打中の二重実行防止、完了後のEnter再試行を確認した。

通信を意図的に保留し、父猫→母猫、本猫→両親コピーの順番、ID変更後に古い結果を捨てる動作、ID欄から保存を押す1回の操作で呼び出し完了を待って3世代を保存できることも確認した。不正ID・未登録ID・未保存確認のキャンセルと再試行も確認した。

合成DBの既存レコードに「名前の続き」「摘要2」を設定し、画面から入力欄が除かれていること、他の項目を編集・保存しても両方の値がDBに残ることを確認した。320〜1440pxの7幅、390pxの文字200%でも横はみ出しはなく、スマホとPCの画像を確認した。今回の検証は合成DBだけで行い、既存の血統データは変更していない。
