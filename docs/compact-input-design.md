# 業務用フォームの入力幅と配置

## 今回の範囲

2026年10月18日、利用者から印刷以外の動作確認が済んだとの報告と、説明を省いた業務用の画面、入力する桁数に合わせた欄幅への改修依頼を受けた。この依頼を実装範囲とする。既存の一つのフォーム、保存、呼び出し、先祖の開閉、PCの3世代表示を維持し、欄幅・並び・余白・文言を調整する。

既存Supabaseの`pedigrees`全13,868件を読み取り専用で集計した。空欄を除いて前後の空白を取り除いた文字数を使い、個別の猫名・所有者名はこの文書へ転記していない。現時点の分布を表示幅の判断に使い、保存できる文字数の制約には変換しない。

## 入力幅の根拠

95%値は、入力済みの値の95%が収まる文字数を示す。幅は数字の幅を基準にし、左右の余白と項目名が収まる最低幅を加える。画面より広い欄は画面内へ収める。

| 項目 | 95%値 | 最大値 | 表示幅の方針 |
| --- | --- | --- | --- |
| 本猫・呼び出しID | 6桁 | 6桁 | 今後を見込んで7桁分 |
| 猫種コード | 2桁 | 3桁 | 3桁分。名称を右に併記 |
| 色柄コード | 3桁 | 3桁 | 3桁分。長い名称は右側で折り返す |
| 性別コード | 1桁 | 1桁 | 1桁分と項目名の最低幅。名称を右に併記 |
| 兄弟・姉妹の頭数 | 1桁 | 1〜2桁 | 2桁分と項目名の最低幅 |
| 誕生日・登録日 | 10文字 | 10文字 | 10文字分 |
| 本猫の名前・名前の続き | 18・16文字 | 23・17文字 | 26・24文字分 |
| 本猫の目色 | 6文字 | 10文字 | 10文字分。誕生日と同じ行へ配置 |
| 繁殖者・所有者 | 16文字 | 18文字 | 20文字分 |
| 本猫の称号 | 8文字 | 23文字 | 通常12文字分。長い既存値は欄内で編集可能 |
| 他団体No | 17文字 | 21文字 | 24文字分 |
| 摘要1・2 | 19・22文字 | 各32文字 | 日本語もあるため28文字分を基本とする |
| 父母・先祖の名前 | おおむね21〜23文字 | 305文字の例外あり | 26文字分。例外の値を切り詰めない |
| 先祖の称号 | 世代・父母別に8〜20文字 | 23文字 | 24文字分 |
| 父母・先祖のナンバー | 20文字 | 23文字 | 24文字分 |

マスタ全体では猫種112件、色柄407件、性別4件。名称の最大はそれぞれ20・33・6文字である。コード欄を名称の長さに合わせて引き伸ばさない。

## 優先する修正

| 優先度 | 変更レベル | 対象箇所 | 問題・根拠・業務への影響 | 具体的修正 | 確認条件 |
| --- | --- | --- | --- | --- | --- |
| P1 | L2 | ID呼び出し・本猫情報 | 短い値も行幅を使い、縦移動が増える | 内容別の幅と折り返し配置。コードと名称を横並びにする | 7桁IDが読め、320〜1440pxと文字拡大で横はみ出しなし |
| P1 | L2 | 本猫・先祖の入力欄 | 文字数にかかわらず同じ幅である | 誕生日・登録日・目色、頭数・称号を収まる幅で同じ行へまとめる。名前等は長さに応じた幅を持つ | 入力文字16pxとタップ領域44px以上をスマホで維持。長い値を保存・再表示できる |
| P2 | L1 | 名称案内・先祖ラベル・保存欄 | 業務で不要な案内と繰り返しが面積を使う | 名称の操作説明を削除。父母の区切り内の「父 名前」等は表示を「名前」にし、読み上げ名は維持。保存欄の見出しと未保存表示を短くする | 項目名・読取名・エラー・保存結果・閲覧専用状態を判別できる |

## 配置変更の影響

| 項目 | 内容 |
| --- | --- |
| 問題 | ID・コード・頭数の欄が内容に比べて大きく、スマホでの上下移動が多い |
| 変更案 | 内容別の欄幅、短い項目の横並び、コードと名称の横並び。幅が足りなければ次の行へ送る |
| 得るもの | 項目と入力する値の長さが対応し、短い項目を同時に確認できる |
| 失うもの | 全欄の右端が揃う見た目と、一部の長い例外値の全文同時表示。例外値は入力欄内の横移動で確認・編集する |
| 代替案 | 全欄を現行幅のまま保ち、説明と余白だけ削る方法。短い項目が縦に続く問題は残る |
| 変更レベル | L2。既存の情報構造・主要操作を維持した配置変更 |
| 承認 | 今回の利用者の具体的な改修依頼の範囲で追加承認不要。L3の変更は含めない |
| PCへの影響 | 本猫の複数列と3世代の並列表示を維持。欄を内容別の幅へ変更 |
| スマートフォンへの影響 | 短い項目を横に並べ、長い項目は幅が足りなければ折り返す |
| タブレットへの影響 | 本猫は収まる幅で2列、先祖の開閉方式は現行どおり。欄幅に応じた折り返しを検証する |
| 操作数への影響 | 入力・呼び出し・保存に必要な操作は増やさない。入力順の一部は横並びになる。時間短縮率は未測定 |
| 情報密度への影響 | 短い項目の横並びと案内削除で同じ範囲の情報を増やす。文字縮小は行わない |
| 一覧性・俯瞰性への影響 | 本猫の短い項目を同時に確認しやすくする。検索一覧とPCの3世代比較は維持 |

## 検証

型チェック・本番用ビルドと、既存の単体テスト9件が成功。合成DBとローカル認証を使ったブラウザー検証15項目も成功した。新規・編集、父母の3世代展開、重複表示、競合検知、きょうだい登録、閉じた先祖の保存、閲覧専用、ログアウトを含む。今回はPDF本体を変更しておらず、実際の台紙への印刷は未確認。

320・390・768・1023・1024・1280・1440pxでフォームと一覧を確認し、390pxで文字200%に拡大しても横はみ出しがないことを確認した。スマホの入力文字16px、項目名14px、入力・保存操作の高さ44px以上を維持した。

最終の幅確認では、全7幅で呼び出し欄の実測が約82pxとなり、7桁の表示とカーソルの余白を確保した。10桁の値も保持できる。最大33文字相当の合成色柄名、3桁コード、2桁頭数でも横はみ出しはない。390pxでは誕生日・登録日・目色が同じ行に収まり、文字200%では折り返す。日本語フォントを設定した検証環境で、スマホ・タブレット・PCの画像も確認した。

実機の入力感と実際の台紙への印刷は利用者による確認対象とする。今回の表示確認で既存の血統データを変更していない。
